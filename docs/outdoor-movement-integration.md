# 屋外移動のシステム接続メモ

2026-10-11。地図UIは採用済み。正式シナリオは作成中のため、以下は担当間で共有する接続待ち項目であり、新しい本編や保存形式を定めるものではない。

## 採用済みのUIとの境界

UIは候補の地図表示・行き先選択・移動確定・取消を担当する。移動候補と実行可否の決定、時刻・進捗・到着ノードの更新はシステム側で扱う。
ピンの選択と取消ではGameStateを更新しない。確定時に候補を再検証し、解放条件が変わっていた場合は現在地に留める。二重入力で移動やイベントを重複実行しない。

## 正式シナリオから必要になる情報

| 項目 | 用途・現状 |
| --- | --- |
| 場所ID・表示名・建物内外の区分 | 地図の地点と移動先ノードの対応。現在の3地点は仮。 |
| 地図上の座標、背景・プレビュー画像、短い説明 | 正式素材・場所が決まった段階で差し替える。画像パスを会話本文に埋め込まない。 |
| 移動経路と到着ノード／シーン | どこからどこへ行けるか、屋内への入口、到着時の人物・調査対象・喫煙可否を復元する。 |
| 判明・解放・移動可否の条件 | 既存の取得情報・フラグと照合する。未判明・判明済みだが行けない場所の扱いは未確定。 |
| 移動時間・日時の更新規則 | モックは時刻を進めない。本編の規則と現在の日時管理が決まってから接続する。 |
| 初回・再訪の到着イベント | 移動確定後の順序、イベント完了後のFree Action復帰先を指定する。 |

現在地を独立した保存フィールドへ追加する必要があるかは未決定。既存のnodeId／sceneIdから導出できる場合は重複保存を避ける。GameState・SaveData version 2の変更が必要なら、互換性と移行方針を確認してから実装する。

## 接続時の受入基準

- 表示した候補と、確定時の実行判定が一致する。現在地には移動できない。
- 選択・取消では現在位置・時刻・取得情報を変えない。
- 正常確定で背景・人物・喫煙可否・調査対象を到着先へ切り替える。
- 移動時間・初回イベントの更新は1回だけ。連打・条件変更時に重複や無効な移動を起こさない。
- 到着ノードの保存・ロード後に同じ場所とFree Actionを復元する。
- 本編とDEVサンプルの素材・情報・保存処理を混在させない。
