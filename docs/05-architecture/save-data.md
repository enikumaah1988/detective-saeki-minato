# 保存データ・保存枠・互換性

対象は既存の保存設計。操作・確認画面は[保存と設定の操作](../01-game-design/save-and-settings.md)、状態項目は[状態設計](state-and-scenario.md)を参照。README、保存枠改定、既存の型・保存モジュールとの照合により、旧記述を現在の契約から分離している。

## 形式と保存先

| データ | 契約 |
| --- | --- |
| GameState | scenarioId、nodeId、flags、heardTopics、inspectedTargets、acquiredInformation |
| SaveData version 2 | GameStateにversion: 2を付けた形式。表示用の表情・全角化・ページは追加しない |
| 保存枠コンテナ | detective-saeki-minato.slots.v1、コンテナversion 1。AUTO1枠＋手動3枠。コンテナ版とゲームデータ版を混同しない |
| 枠内情報 | ゲームデータ、保存日時、ラベル、最大2000件の会話履歴を同じスナップショットに保持 |
| 旧単一保存 | detective-saeki-minato.save.v1。初回に手動枠へ移行し、旧キーを保持する |
| 設定 | 文字速度・BGM/SE音量は進行保存と独立。音量は0～100の数値を保持 |

## 復元・失敗処理

旧version 1・2の復元に対応する。未知のscenarioId・nodeId、破損JSON、不正形式、未対応versionは検査して拒否する。形式・保存位置の変換と保存先アクセスは既存モジュールで処理する。旧version 1から改稿導入へ戻す扱いと、version 2の進捗補完・互換ノードは既存ルールを維持する。

旧履歴はシナリオID・ノードIDが一致する場合に移行する。容量不足・保存先障害・破損時に、読み込めない既存JSONを正常な空保存として上書きしない。設定や履歴の障害をゲームの保存成功と混同しない。

会話ロードは保存ノードの先頭ページから開始する。メニュー・履歴の開閉だけなら現在ページと文字送り位置を維持する。表情はノード定義から再現し、保存状態を増やさない。旧情報の補完は対象となる旧保存に限定し、新保存へ未読の事実を一括付与しない。

## AUTOの境界

既存の場面または話題段階の節目で更新する。同じ場面の人物選択、任意話題の追加、通常の文章送りで連発しない。初回マウント・ロード・最初からの復帰だけでは更新せず、通知しない。話別の節目は既存savePhaseId／savePhaseMarkersと取得情報から導出する。

クラウド同期、エクスポート、インポート、削除操作等をこの整理で追加・採用しない。進捗ID・保存スキーマを変える場合は従来の事前相談が必要。
