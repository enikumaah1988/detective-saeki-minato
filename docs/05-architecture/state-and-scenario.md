# 状態管理とシナリオの契約

共通の技術設計。作品の採用・事件本文は[02 物語](../02-story/README.md)、画面操作は[01 ゲーム仕様](../01-game-design/actions.md)、永続化は[保存設計](save-data.md)へ分離する。既存README、旧PC仕様のUI／システム分担、ver0.03接続記録を整理したもので、新しい汎用化や状態項目は追加しない。

## 責務

| 層 | 担当 |
| --- | --- |
| src/data/scenario | 台詞・分岐・条件・取得情報・話別の演出指定。revisionData、buildRevision、revisionCommands、revisionRecords等 |
| src/features/storyの進行・状態処理 | 状態遷移、表示と実行時の条件判定、人物・記録・時計・選択肢の導出 |
| UI | 判定済み内容の表示と入力要求。独自の進行先・未解放項目を補充しない |
| 保存モジュール | 形式検証・旧データ変換・保存先操作。画面へ分散させない |

## 状態・シーン

GameStateはscenarioId、nodeId、flags、heardTopics、inspectedTargets、acquiredInformationを保持する。背景・人物・記録・話題順は必要な既存状態と定義から導出する。表示用の全角数字・改ページ・表情を進捗データへ書き込まない。

シーンは背景・人物構成・位置・登場条件を持ち、ノードのsceneIdから解決する。2人は左右、3人は左・中央・右を明示し、重複人物を許可しない。旧単体Stageも読み込める。会話ノードのexpressionsはシーンの表情だけを上書きし、不在人物を追加しない。同じ会話列で引き継いだ表情は各ノードへ確定するため、ロード履歴に依存しない。[表情契約](../04-art/character-expressions.md)を参照。

## 遷移・入力・取得

- UIの表示可否とシステムの実行可否に同じ条件を適用し、非表示項目への直接要求も拒否する。
- 発行元ノードと入力世代を検証し、選択演出・ロード・再訪・メニュー前の古い要求を実行しない。
- 会話の途中ページ・全文表示では取得情報を更新せず、最終読了時に一度だけ完了処理する。入場時の処理と読了時の処理を区別する。
- Free Actionの0件復帰、parentによる戻る、topicTransitions、conditionalNext等はデータ側で指定する。戻るだけで取得情報を付与しない。
- 互換用のシナリオID・ノードID・legacyOnlyは、未使用に見えるだけで削除しない。話別の移行条件は[Episode 01](../02-story/episode-01/progression.md)を参照。

旧稿のデータやDEVモックを、現在の本編仕様へ一括適用しない。旧データとの互換性と、正式な物語設定・素材採用状態の維持を両立する。
