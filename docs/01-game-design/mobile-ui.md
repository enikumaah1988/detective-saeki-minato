## 画面構成とレスポンシブ配置（未検証）

- PCとの共通原則は右側の話題／提示物一覧、人物選択状態の共有、会話中とコマンド中の表示分離、独立した「話す」「見せる」「推理する」。既存の青黒・チャコール、オフホワイト、真鍮色を引き継ぐ。
- 横幅に余裕がある場合は、話題一覧の左横へ「見せる／話す」切替ボタンを置き、狭い画面では話題一覧の上へ移すB案。**幅だけで一律に決めず、セーフエリアを除く有効幅・高さ、人物の顔、話題の文字量を見て切り替える。**
- 検証起点として、見せるボタン幅64〜76 CSS px・高さ56〜64 CSS px、文字14〜16 CSS px、アイコン20〜24 CSS px、話題タッチ高さ48〜56 CSS px、要素間隔約8 CSS pxを試算。**端末実機では未確認で確定値ではない。** 最低でも押しにくい縮小ボタンを避け、アクセシビリティと端末の表示倍率を検証する。
- 話題一覧は必要時に縦スクロール可能とし、切替ボタンは一覧と一緒にスクロールさせない。長い話題名を無理に縮小せず折り返す。切替後もボタンの位置を変えず、「話す：黒田」のように現在の行動を明示する案。
- 台詞送り中は一覧と切替を隠し、台詞ウィンドウを優先。推理回答は選択状態を視認できるようにし、**選択と確定を別操作**とする。S08の図面は細かい自由座標タップを要求せず大きな候補地点または対応する一覧で選べるようにする。S21は候補発言をスクロールしても選択内容が確認できる設計を検討する。
- 3人登場時も、立ち絵をUIに合わせて無条件に縮小・移動しない。シーンが指定する左右・中央の配置と表情を優先し、顔を覆うなら**操作側**を再配置する。同じ場面に3人いることと3人を同時描画することは区別する。
- 「見せる」の切替操作で即時に物品を提示しない。候補1件なら対象名のある実行項目、複数件なら候補選択。候補0件はコマンドを出さない。誤提示は進行不能を生じさせない。
