# 第1話 ver0.03 進行と組込仕様

2026-10-12。ゲームTS・UI・素材は未変更。今回の改稿とJSONを接続基準とし、ver0.01の過去の転落事件を維持する。

## JSON

第1話_改稿_ver0.03_第1部.json～第4部.json。scene配列はid、part、locationId、roomId、sceneTime、intro、people、required、ask、speak、inspect、think、organize、exit、endingを持つ。台詞行はspeakerId・text、必要な行にgrants。制作指示はlinesに含めない。

- locationIdはoffice／company／building／police。roomId末尾exteriorは建物前。sceneTimeの内部年は2026年、表示は年なし。証拠の内部年は2024年、画面は年なし。
- introのline.grantsはその行の表示後に付与。黒田・刑事・直人の名乗りを、追加の確認クリックへ置換しない。
- peopleはその場の候補。前提を満たすactionがある相手だけ会話対象に表示。受付・管理人は調べるまで会話を出さない。名前取得前の表示名は女性／管理人／部長など。
- ask／speakは相手選択後に話題選択。requires取得に応じて追加話題を開く。一問で別の話題の情報まで取得しない。
- speak内interaction=item-useはitemIdとpersonIdでアイテム使用に接続し、通常話すに重複表示しない。
- interaction=phone、remoteOnly=trueは電話相手。現場のpeopleへ追加しない。着信はtriggerMode=automatic-after-entry。話者が変わっても背景は変えない。
- thinkはP1-04とP3-07のみ。必要情報取得後の内心。P3では別の部末P3-08より前。
- organizeはP2-10とP4-05のみ。問題・正答・ヒント・successLinesを含む。正解済みの問を保持する。
- organize.grantsは全問正解後にのみ付与する。linesを表示しただけで推理完了にしない。検証スクリプトは正答した必須経路の到達可能性を調べるもので、組込側の推理UIを実行した検証ではない。
- requiredは必須action ID。exit.requiresは必須actionのgrantsを含む。introで既に付与した情報には追加操作不要。
- 同室は「次へ」、部屋間は部屋名、屋内の出口は「外に出る」。外↔マップ↔別建物の接続は組込側が生成。本話に不要な移動イベントは追加しない。
- endingは退室・部末・時間経過。IT01の写真受取は既存の中央提示→OKを利用する。
