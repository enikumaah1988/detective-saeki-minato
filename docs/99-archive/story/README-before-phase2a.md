## 更新方針

- ユーザーが採用した内容、暫定方針、未承認の提案を区別する。
- 方針変更時は現行設定を更新し、旧案を相談履歴へ残す。
- 未委任の変更は提案として区別する。委任された制作判断は決定理由を残し、個別のユーザー承認と混同しない。
- ゲーム実装、UI、素材仕様への反映は別作業とする。
- GitHubではゲームと同じリポジトリの docs/story/ で管理する。変更はブランチとPRを通す。

現行資料は制作途中であり、完成シナリオや実装用データではない。
