# 制作ロードマップ

更新日: 2026-10-10

本書は制作の優先順位と将来のToDoを管理する。確定したゲームUI仕様は[pc-game-ui.md](pc-game-ui.md)、具体的な実装作業と受入条件は[GitHub Issues](https://github.com/enikumaah1988/detective-saeki-minato/issues)で管理する。

## 現在の優先事項

「探偵 佐伯湊」の4部構成のサンプル制作とプレイ検証を優先する。会話・自由行動・情報収集・推理から次フェーズへの進行を、実際に遊んで確認し、必要な改善を小規模なIssueに分けて進める。

シナリオデータと再生処理の分離は維持する。将来の汎用化だけを目的とした機能追加や大規模な構造変更は、現段階では行わない。

## 優先順位と完成目標

サンプルを完成させ、MinatoEngineを整えた後は、シナリオと素材の制作に集中できる状態を目指す。サンプルは4部構成とするが、将来のMinatoEngineは部数を固定せず、作品側で指定できる方針とする。

| 順序 | 作業 | 完了の目安 |
| --- | --- | --- |
| 1 | 現在の操作・表示の改善。Issue #7・#8、推理時のコマンド表示、画面全体・Enterでの送り、フォント・話者名・下線。 | 第1部を無理なく遊べる。各Issueの進捗はGitHubで確認する。 |
| 2 | 4部のストーリーとフローを整理し、登場人物・場所・証拠・推理条件の不整合を確認する。 | 開始から結末までの進行が決まる。ストーリー生成ツール自体の実装は前提にしない。 |
| 3 | 必要な正式キャラクター、表情・角度・ポーズ、各場所の背景、証拠画像を整理して制作する。 | 必要な素材が揃い、デモ素材を置き換えられる。 |
| 4 | シナリオに必要な探索・推理を実装する。移動、マップ、対象選択、物の中央表示、必要な証拠提示など。 | 4部を通して進行できる。 |
| 5 | バックログ、記録、基本の保存・復元、設定、中断・再開を整える。スマホWeb表示・タッチ操作を仕上げる。 | PCとスマホで読み返し・中断・再開ができる。 |
| 6 | ロゴ・ファビコン、開始・終了画面、ストーリー選択画面、部間映像、採用する音、クレジットを整える。 | 作品として開始から終了まで一周できる。 |
| 7 | PC・スマホWeb版を検証して配布する。 | 両PC解像度とiPhone Safari・Android Chromeの実機で通しプレイ・保存復元を確認し、他の人に遊んでもらえる。 |
| 8 | サンプルの経験からMinatoEngineを共通化する。 | 別の短いシナリオをエンジン本体のコード変更なしで動かせる。 |
| 将来 | ネイティブアプリ化。 | 対象OS・配布方法を決めて個別に計画する。時期やMinatoEngine化との前後関係は未定。 |

アーキテクチャは現段階から簡潔に文書化し、各段階で更新する。小画面への対応も初期から考慮し、配布直前まで先送りしない。縦持ち・横持ちの対応方針はレイアウト着手前に決める。

複数セーブスロット、オートセーブ、オート送り、既読スキップ、記録の関連表示などは、まず基本のプレイが成立した後、検証結果から優先度を判断する。

### 優先8：MinatoEngine化

- **状態**：将来構想・未着手
- **目的**：現在のシステムを、推理ゲーム用フレームワーク「MinatoEngine」として別作品でも利用できる形にする。
- **検討時期**：「探偵 佐伯湊」のサンプルでゲーム体験と必要な機能が固まった後。
- **検討内容**：作品固有の設定・素材・シナリオと共通の再生・進行処理の境界を見直し、共通化する範囲を判断する。シナリオの外部ファイル化、入力・フロー作成・整合性検証の仕組みもその際に検討する。以降はシナリオと素材の追加を中心に作品制作できる状態を目指す。
- **今は決めないこと**：公開API、外部データ形式、編集ツール、対応する推理方式、公開・配布方法。これらは確定仕様や実装予定ではない。


切り出し候補：作品固有処理の棚卸し、設定と再生処理の分離、シナリオ入力形式、フロー作成・検証、別シナリオでの動作確認。範囲はサンプル検証後に決める。

## 管理方法

- 将来構想と優先順位は本書に残し、方針が変わったときに更新する。
- 着手する内容が具体化したら、目的・対象範囲・受入条件を持つ小規模なIssueへ分割し、該当項目にリンクを追記する。
- Issue化した項目は「検討中」「着手」「完了」などの状態を更新する。詳細な進捗はIssue／PRに集約し、本書に重複して記録しない。

- Issueタイトルに優先段階（例：`[優先1]`）を含め、候補行にIssueリンクを追記する。
- Issueには目的・対象範囲・受入条件・前提Issue・対象外・検証方法を記載する。未確定事項が多ければ仕様整理と実装を分ける。
- 通常は1Issue・1ブランチ・1PRで進め、人間のレビュー・マージ後にWSL側mainを最新化する。
