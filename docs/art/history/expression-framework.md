## 1. 共通表情辞書
通常は全員必須。その他は全員分を必須にしない。喜怒哀楽は検索・整理の分類であり、ファイル名には分類名を重複して入れず表情キーを使う。
キーは英小文字とアンダースコアのみ。定義が決まったキーを同じ意味のまま維持し、同義語で増殖させない。

| 分類 | 日本語名 | 表情キー | 意図・描画の基準 |
|---|---|---|---|
| 基準 | 通常 | neutral | その人物の普段の顔。必ずしも無表情ではない。鳴海の通常は軽い笑み。 |
| 喜 | 微笑み | smile | 通常から目元・口角がわずかに緩む、小さな好意・気遣い。 |
| 喜 | 喜び | happy | 嬉しさが明確に表れる。笑いの動作は必須ではない。 |
| 喜 | 安堵 | relieved | 緊張がほどける。目元・眉・口元の力が抜ける。 |
| 怒 | 苛立ち | irritated | 不快感がにじむ。口元や眉に力が入るが強い怒りには達しない。 |
| 怒 | 怒り | angry | 怒りが明確。怒鳴る顔が必須ではなく、静かな怒りも含む。 |
| 哀 | 悲しみ | sad | 個人的な悲しさが表に出る。涙は必須ではない。 |
| 哀 | 沈痛 | pained | 重い事実や苦しみを受け止める。泣くより顔が重くなる方向。 |
| 楽 | 楽しげ | amused | 会話や状況を楽しむ軽さ。口を開けた笑いは必須ではない。 |
| 楽 | 笑い | laugh | 実際に笑っている表情。人物に応じた口と目の変化。 |
| 補助 | 真剣 | serious | 重要な話や判断に集中。怒りと区別する。 |
| 補助 | 疑念 | skeptical | 証言・説明を疑い、確かめようとする。 |
| 補助 | 驚き | surprised | 予想外への反応。人物ごとに強弱を変える。 |

共通の表情名でも強度・目線・口の開きは人物ごとに異なる。似すぎる差分は別画像を増やさず兼用候補にする。

## 2. 再利用できる追加表情辞書

## 4. ディレクトリと短いファイル名（ユーザー承認）
ゲーム用画像ルートはimages/。人物別ディレクトリに分け、ファイル名は表情キー.pngとする。

```text
images/characters/minato/neutral.png
images/characters/mio/smile.png
images/characters/narumi/playful.png
images/characters/segawa/reluctant.png
```
これらは未制作素材も含む命名例。長い「人物__衣装__表情__角度__所作__版.png」案は廃止する。
人物キーはminato / mio / narumi / okumura / segawa。表情キーは上記辞書に従う。
衣装・角度・所作は必要時にディレクトリ階層で区別する。追加階層の具体形は未決。情報を全てファイル名へ詰め込まない。
画像を反転すると髪の分け目や小物も変わるため、自動反転の採用は未決。
表情×角度×所作×衣装の全組み合わせは制作しない。
詳細な全素材の構成は[image-layout.md](image-layout.md)を参照する。

## 5. 制作版とゲーム用画像の管理
試作・旧版・生成条件はproduction/に保持し、版番号と採用状況を台帳で管理する。
images/には正式採用したゲーム用画像を置く。ゲーム用ファイル名には版番号を付けず、採用した制作原本を台帳で特定する。
既存prototypeファイルは改名・移動せず、今回の分類により完成素材扱いにしない。
ゲームの論理キーを使う場合、例としてminato.smileとimages/characters/minato/smile.pngを対応させる。
未制作の画像を対応表へ登録しない。兼用先や通常表情への切替は実装時に明示する。
既存ゲームコードとsrc/assets等の配置は変更しない。現時点では構成・命名規則の文書化のみ。
## 6. 更新手順
1. ユーザーの表情要件を共通辞書へ照合し、人物別の必要性・固有の描き分けを記録。
2. 必要な組み合わせだけ生成し、バージョンを付けて保存。
3. 実画像を確認して状態を更新。採用判断を台帳へ反映。
4. 同義語・不要なキー増殖・仮案の確定扱いを避ける。
5. 命名規則の変更は移行案を提示し、既存画像を無断改名しない。

## 表情確認シートの共通仕様 v0.1（最新）
- 【ユーザー確定】表情枠は最大8。通常の全身像は別枠であり、8表情に含めない。表情側にも通常を含める。
- 【確定】左に通常全身像、右に4列×2段の表情枠。8種類未満は残りを「追加用」の空欄にする。空欄を埋めるために表情を増やさない。
- 【確定】8種類を超える場合は基本表情を優先し、超過分をシートに載せない。省略は不要・削除を意味せず、人物別台帳には残す。超過だけを理由に別ページを自動制作しない。
- 【優先順位の運用案】通常は必ず表示。人物別に基本として選んだ表情を先に置き、余った枠に固有表情を置く。基本／固有の区分は人物別に記録し、共通辞書全体を基本必須と誤解しない。8枠以上の優先候補がある場合は表示順を決めてから生成する。
- 【ユーザー確定】全人物の表情確認シートを1920×1080pxの横長キャンバスに統一。薄いニュートラルグレーの背景、同じ全身領域、枠配置、顔の表示サイズ、ラベル形式を使用。
- 表情は顔〜肩の範囲。人物らしい感情の強弱を保つ。全身像は髪から靴まで切れないようにする。
- 個別ゲーム用立ち絵の透過・全身仕様は別管理。シートの背景やサイズを個別素材へ適用しない。
- 生成出力の実寸を確認する。生成時のサイズ指示だけで共通寸法になったと主張しない。必要な寸法調整は人物比率を歪めず、原本を保持して行う。
