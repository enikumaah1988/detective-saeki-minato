# 検証手順とCI

ゲームの既存チェックを使用する。実行結果は当該PRへ記録し、文書内の過去件数を今回の成功と扱わない。

~~~sh
npm ci
node --test --test-isolation=none tests/*.test.mjs
npm ci --prefix tools/lint
npm run lint
npm run build
~~~

- lint依存は[tools/lint](../../tools/lint/README.md)でゲーム用TypeScriptから分離する。警告上限を引き上げて隠さない。
- ブラウザーは外部Playwright／Chromiumが必要。SAEKI_PLAYWRIGHT_PATHにモジュール、SAEKI_PART1_URLに本編URL、SAEKI_BASE_URLに旧デモURL（?scenario=gray-testimony-part1-demo付き）を指定する。各テストの通常タイトル／DEV直行の前提を確認する。未設定のブラウザー項目はスキップであり確認済みではない。
- PCの主な確認サイズは1920×1080・1366×768。Firefox／Safari・スマホの実機保証と区別する。人の所要時間・難易度・没入感は自動完走だけでは確認できない。
- 開始・再開は`tests/titleScreenBrowser.test.mjs`と`tests/uiSaveSlotsBrowser.test.mjs`を併用する。通常URLではタイトルのNEW GAME／CONTINUEを経由し、タイトルのCONTINUEダイアログと本編MENUのLOADを区別する。保存なし・手動枠・AUTO・旧単一保存・破損データ、再起動後の設定、未保存進行の取消を確認する。現行のNEW GAMEは直接本編を開始し、未実装の作品選択画面を成功条件に加えない。
- `tests/historyResumeBrowser.test.mjs`はPCの2サイズで、文字表示途中の履歴連続開閉、停止と再開、背面入力の拒否、複数ページの位置保持、次ノードへの入力復帰と履歴の追加を検証する。長文はテスト時だけ差し替え、タイプライターの時間はPlaywrightの時計で制御する。
- `tests/mobileLandscapeBrowser.test.mjs`は667×375・844×390・915×412をChromiumの横向きタッチ環境で確認する。外部Playwrightと本編URLを上記の環境変数で指定し、HUD・会話履歴・保存／復元・調査記録・選択肢・地図を実際にタップする。各対象の画面内配置と中心点のヒット判定も調べる。既存の比例縮小レイアウトを対象とし、スマホ専用UIの採用やiOS／Android実機での押しやすさ・ブラウザー固有挙動の保証とは区別する。
- ブラウザーサーバーはロジックテストと別のViteキャッシュを使い、終了時は自分が開始したものだけを止める。環境固有の[Windows設定](../../tools/windows-vite.config.mjs)を一般環境へ無条件に適用しない。
- 文書整理ではMarkdownリンク・相対パス・参照・非対象ファイルの保持を確認し、影響に応じた既存テストを選ぶ。アプリ挙動を変えない文書変更でゲームのビルドや全ブラウザーを省略した場合は、その理由をPRに記す。

既存[GitHub Actions](../../.github/workflows/ci.yml)はPRとmainへのpushで、LFS取得、Node 24、npm ci、Nodeテスト、分離lint、型チェック・ビルドを実行する。CIが成功しても、環境未指定でスキップされたブラウザーを確認済みとしない。

## Episode01 ローカルE2E（Playwright Test）

Node.js・npm・Git LFS素材を用意し、リポジトリ直下で実行する。Windows PowerShellでも同じコマンドを使う。

~~~sh
npm ci
npm run test:e2e:install
npm run test:e2e
~~~

`@playwright/test`は開発依存だけに追加する。既存の外部Playwright方式には通常タイトルから全編を操作する共通ランナーと失敗証跡の管理がないため、本項のE2Eはプロジェクト内の固定バージョンを使う。配布ゲームには組み込まない。既存Nodeテストと外部環境を使うブラウザーテストは維持する。

`playwright.config.mjs`が127.0.0.1:5290のViteを開始・終了する。通常開発ポート5187とは別で、既存サーバーは再利用しない。使用中ならエラーとなり、他プロセスを停止しない。変更する場合はPowerShellで`$env:SAEKI_E2E_PORT='5291'`を設定する。公開URL・デプロイ・Work接続は不要。Viteキャッシュは`.cache/e2e-vite`に分離する。LinuxではPlaywrightのOS依存ライブラリも別途必要になる場合がある。

PC 1920×1080とタッチ対応Chromiumの横844×390で、タイトル→NEW GAME、必須の聞く・調べる・考える前後、S08の戻る／通路選択、S09の移動不可、S17/S23/S27の全設問の誤答・再挑戦・正答、BAR有無のS30到達、画面のSAVE/LOAD、警察場面前後の進捗・調査記録表示を検査する。ルート探索には既存reducerを使い、ブラウザー内の進捗を注入しない。表示ラベルと会話本文、独立した期待順序・必須条件も照合する。全選択肢・任意会話の組合せや実機の操作性保証ではない。

S08/S27の会話順とS26注記非表示は#235〜#237の修正を取り込んだ状態が成功条件。修正前のmainでは該当検査が失敗する。検証時は対象SHAと一時統合の有無をPRへ記載し、修正のコードをE2Eブランチへ重複実装しない。正式なmainでの再確認は修正PRのマージ後に行う。

`npm run test:e2e -- --grep タイトル`で短い導入確認、`npm run test:e2e -- --project pc`でPCだけ実行できる。`playwright-report/index.html`が結果、`test-results/`に代表スクリーンショットと失敗時のスクリーンショット・`trace.zip`が残る（すべてGit対象外、次の実行で更新される）。必要な証跡は次の実行前に別の場所へ保存する。`npx playwright show-report`または`npx playwright show-trace <trace.zipのパス>`で確認する。失敗テストの自動再試行はしない。横幅・会話枠のはみ出し、画面内のタップ対象と中心ヒット判定も確認するが、スクリーンショットの芸術的判断やFirefox/Safari、iOS/Android実機の保証とは区別する。

## 配布用ビルドの確認

Git LFS素材・依存関係と外部Playwright／Chromiumを用意し、`SAEKI_PLAYWRIGHT_PATH`を設定して`npm run test:distribution`を実行する。Chromiumの格納先を既定から変えた環境では`PLAYWRIGHT_BROWSERS_PATH`も指定する。このコマンドは型チェックと本番ビルド後、`dist`だけを一時的な静的HTTPサーバー（127.0.0.1・空きポート）で配信し、終了時にブラウザーとサーバーを閉じる。開発サーバーの起動や`SAEKI_PART1_URL`の設定は不要。

- 全配布画像・フォントのHTTP取得、Content-Type・ファイルヘッダー・LFSポインター混入を検査する。
- Chromiumの1366×768でタイトル画像、新規開始、会話進行、画面操作によるSAVE、再読み込み後のCONTINUE、保存位置・履歴・音量設定の維持を確認する。`?dev=1`でもDEV操作が表示されないこと、ブラウザー例外・HTTPエラーがないことも検査する。
- 明示コマンドはPlaywright未設定、Chromium未導入、ビルド失敗、検証失敗で非ゼロ終了する。通常のNodeテスト一括実行ではPlaywright未設定時にこのブラウザー項目をスキップする。既存CIは外部ブラウザー未設定のため配布ブラウザー検証を保証しない。

手動確認は`npm run build`後に`npm run preview -- --host 127.0.0.1`で表示されたHTTP URLを開く。サーバー停止はCtrl+C。配布物は`dist`全体であり、現行設定の配置先はHTTPサイトのルート（`/`）。`file://`でHTMLを直接開く方式は対象外。サブディレクトリ配信は現行の既定設定で保証せず、配信先に合わせたViteのbase設定と再ビルド・別検証を要する。

この確認は配布物からの基本起動と保存復帰を対象とし、全シナリオ完走、全画像の目視品質、音素材の再生、Firefox／Safari・スマホ実機・外部ホスティング固有の設定まで確認済みとは扱わない。

## 連続入力の検証

`tests/rapidOperationsBrowser.test.mjs`は移動通知の同一フレーム連打、移動開始直後の戻る入力、待機中のアンマウントを検査する。PCクリックと横向きタッチ環境では実StoryPlayerの会話・選択肢・調査・移動を確認する。同一フレームの入力集中はDOMクリックで再現し、実際のクリック／タップ操作と区別する。

## 戻る操作の検証

`tests/navigationReturnBrowser.test.mjs`はPCの2サイズで、MENU・LOAD・タイトル復帰確認の取消、調査記録・履歴・喫煙の終了、地図の戻る操作を確認する。画面の表示完了を待って閉じ、呼び出し元の焦点・会話ページ・進行位置と保存した全進捗を照合する。「考える」「整理する」は独自の取消ボタンを追加せず、会話を読了してデータ指定先へ戻る経路を確認する。全場面の戻り先や全入力タイミングを網羅する検査ではなく、既存の進行・保存・連打テストと併用する。

## シナリオの進行監査

`node --test --test-isolation=none tests/progressionAudit.test.mjs`で、本編の遷移参照（条件分岐・自動遷移・再実行・親への復帰・0件時の続行・マップ・持ち物・到着イベント・旧保存の変換先を含む）を検査する。現行稿の場面入口・メニュー・非legacy行動が開始点から構造上つながり、各ノードから終了先への経路があることも調べる。旧保存の変換元IDは現行ノードに存在するとは限らず、全互換ノードが新規開始から到達可能という条件は課さない。

構造検査は条件と分岐の優先順を無視した接続の検査であり、実際に選べることの証明ではない。別途、実reducerで必須／任意込みの行動順を逆転した完走、一覧・マップの戻る／取消、全場面の実到達状態と会話・調査一覧・マップ位置のSaveData v2復元後の完走を確認する。代表状態の各表示選択肢を一度ずつ選んだ後も、完走する操作列を探す。失敗時は開始ノード・選択肢と停止位置を表示する。

各操作列は6000操作を上限とする。代表状態と検査した分岐数はテストの診断出力で確認できる。任意行動の全組合せ、全条件の真偽、任意に編集されたセーブ、全てのUI操作を網羅する探索ではない。参照切れ・到達経路の切断・終了不能な循環・取得不能な必須条件を検証用コピーへ混入するテストで、検査が問題を検出することも確認する。既存の全編進行・会話順序・旧保存互換のテストは併用する。

## 進行途中の保存復元

`tests/savedScenarioCompatibility.test.mjs`は、30シーン導入前のmain `b51b4e83ee2d399799376a186750bb58d06d1a88` のシナリオ・reducer・保存処理・話者名解決と、同コミットの`revisionHarness.buildPlaythrough(api, true)`から生成した固定fixtureを復元する。`tests/fixtures/save-v2-before-30-scenes.json`は旧稿のP2-06-menuへの到達状態、直前12件の履歴、選択肢・人物背景・記録IDを保持する。ユーザーの実SAVEを採取したものではなく、実データ固有の破損やorigin違いは別途確認が必要。

`npm run test:e2e -- tests/e2e/save-compatibility.spec.mjs`は独立したブラウザーの保存領域だけにfixtureを配置し、通常のNEW GAME後のゲーム内LOADから旧稿・第1部限定版・全編版・AUTOへ復帰する。枠と履歴の保持、旧単一保存の移行と原本保持、SAVEし直した内容、同一シナリオのLOAD、再読み込み後のCONTINUE、未知シナリオ／ノード／未対応versionの失敗時非上書き、旧稿からタイトルに戻った後のNEW GAMEをPC・横向きタッチで検証する。

`tests/saveProgressBrowser.test.mjs`は調査途中・地図移動直後・推理正解後に、画面操作でSAVE、別状態への進行、LOAD、再読み込み後のCONTINUEと次操作を確認する。全進捗、背景・人物・表情、選択肢・会話・場所日時を比較する。v2の旧ノード変換や保存形式の異常値検査は既存の保存テストと併用する。

## 演出指定の整合性

`node --test --test-isolation=none tests/presentationAudit.test.mjs`で、本編と旧保存互換ノードの背景・人物・表情・話者・場面参照を登録定義と照合する。安全な表示フォールバックを通さずIDを検査し、台詞の表情指定が実際の場面の人物に属することも確認する。未対面の表示条件を持つ人物は場面の一員として扱い、画面外の話者・地の文を立ち絵の有無で拒否しない。旧単体Stageと登録済みの画像なし背景も許容する。

生成前の`RevisionData`についても導入・終幕・各行動・成功時・話題移行の会話行を調べ、生成結果だけの検査で原稿の誤記を見落とさないようにする。検証用コピーへ未登録ID・場面参照切れ・不在人物の表情指定を混入し、検出を確認する。

この検査は登録・指定の構造的整合性を対象とする。画像ファイル自体の存在・内容は既存の素材検査と配布検証を併用する。台詞に合う表情や背景の芸術的判断、全演出の目視、条件の全組合せ、音素材の接続・再生は検証しない。

由来：既存ルートREADME、AGENTS.mdの検証節、[旧開発タスクの型](../project-management/開発タスクの型.md)、現行ci.yml。検証の新しい承認ルールを追加する文書ではない。
