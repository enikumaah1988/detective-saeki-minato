# PC版通常GAME／Free Action UI仕様書

更新日: 2026-10-10

本書は確定したUI仕様を記載する。実装済みを意味するものではなく、現行実装との差分は末尾に分けて記載する。

## 対象・共通デザイン

- PC版の通常GAME、Free Action、共通MENUを対象とする。
- 基準解像度は1920×1080、画面比率は16:9。以下のpx値は基準解像度での値とし、小さいPC画面では同じ比率で縮小する。
- 青黒・チャコール、オフホワイト、落ち着いた真鍮色を使用する。装飾とアニメーションは控えめにする。
- 背景を全面に表示し、その上に人物、会話／コマンド、上部共通UIの順に重ねる。
- 通常GAMEでは背景・人物・会話・共通HUDを表示する。Free Actionでは会話ウィンドウを非表示にする。
- 基準画像は `reference/ui/ui-reference.png`。レイアウト・UI密度・配色を参照し、人物・背景・画風を取り込まない。
- DEVのシナリオ切替はゲーム領域外に置き、送り記号や本編操作と重ねない。
- スマホ専用最適化、INSPECT MODE／MOVE MODEの詳細設計、複数の相手の同時表示は対象外。

## 人物配置（確定）

人物の表示と配置は、Free Actionの有無ではなくシーンの指定で決める。表示人物と話者は別の情報として扱う。

| シーンの人物構成 | 配置ルール |
| --- | --- |
| 湊のみ | 左を標準とする。シーン指定で右も可能。 |
| 湊とほかの人物 | 湊は左、相手は右。 |
| 湊がいない | ほかの人物は中央または右をシーンで指定する。 |
| 相手が複数いる | 当面は右に表示する相手をシーンで指定する。複数の相手の同時表示は別途検討する。湊も表示する場合は左に置く。 |

- 話者が変わっただけでは、表示人物・配置を変更しない。
- 通常GAME／Free Actionが切り替わっただけでは、表示人物・配置を変更しない。
- 人物を変更・移動する場合は、シーン側の明示的な指定によって行う。
- 人物と右側コマンドの重なりは許容する。重なりを避けるためにUIが人物を自動移動してはならない。
- 人物の頭側の位置を基準にサイズを調整し、画像下端の切れ目が半透明会話ウィンドウ越しに見えないようにする。
- シナリオの`scenes`で背景と`characters`（人物ID・表情・配置）を定義し、各ノードの`sceneId`から解決する。同じシーンIDでは話者・ノード種別に依存せず同じ表示を使う。湊と相手の2人まで対応する。人物変更・表情変更・移動はシーン定義または明示的なシーンID変更で指定する。

## 上部共通UI

- 左上にMENU、調査記録、タバコを吸うを横並びで置く。
- 右上には現在地、ゲーム内日時を2段で表示する。
- 上余白24px、左右余白32px。HUD文字28px、HUDアイコン44px。
- 「調査記録」は手帳、「タバコを吸う」は煙の出ているタバコの線画を文字ラベルの左に置く。既存の`UiIcon`（24×24 viewBox、塗りなし、線幅1.5、丸い線端・角、`currentColor`）を共用する。色は文字色を継承し、MENUと同じ44pxの表示寸法、アイコンと文字の間隔12px、縦中央揃えとする。寸法は1920×1080基準で同比率に縮小する。
- HUDアイコンの検証：`tests/hudBrowser.test.mjs`で1920×1080・1366×768のChromium表示を確認。アイコンと文字の中央揃え・間隔・色・線幅、ボタン同士および右上の現在地／日時との非重複、記録の開閉と喫煙演出の開始を検証し、スクリーンショットも目視確認した。外部Playwrightの指定方法はREADMEに準拠する。
- ボタン背景は半透明青黒、控えめな角丸、原則として枠線なし。
- MENU展開時は左側へセーブ、ロード、セーブデータ削除を表示する。
- MENU展開中は右側の自由行動UIを隠し、閉じると現在の選択可能項目を再表示する。背面の会話・自由行動は操作できない。
- Free Actionのコマンド非表示規則は上部HUDの仕様を変更するものではない。上部の未実装操作については現行との差分を参照する。

## 通常GAMEのDialogue Window

| 項目 | 確定値・ルール |
| --- | --- |
| 横幅・位置 | 画面幅90%、水平中央、下部フローティング |
| 高さ・下余白 | 320px、24px |
| 背景 | 青黒、不透明度68%。通常Dialogueにのみ適用し、MENU／Free Action背景と共有しない |
| 枠・角 | 細い真鍮色の枠、控えめな角丸 |
| 発言者名 | 32px、ウィンドウ内左48px・上28px、アンバー |
| 名前下ライン | 短い細線。名前と本文の間隔を増やさない |
| 本文 | 38px、行間1.5、3行分を確保。名前の下20pxから開始し、左端を揃える |
| 送り記号 | 右下の塗りつぶし三角形▼、26px |

- 名前と本文は同じパネル内に上から順に配置する。中央寄せや名前だけの別タブにしない。
- タイプライター表示と進行操作は、以下のページ送り仕様に従う。
- ▼は現在ページの表示完了後に表示し、ゆっくり点滅する。動きを減らす設定では点滅を止める。
- クリック／タップ、Enter／Space、シナリオ進行・分岐、セーブ／ロードを維持する。
- 通常会話ではゲーム領域の背景・人物クリック／タップも既存の会話送り処理を呼ぶ。Enterは会話ボタンへのフォーカスなしでも使え、長押しの反復入力は無視する。会話ボタンにフォーカスしたSpace操作は維持する。MENU、セーブ／ロード、調査記録、喫煙演出、選択肢、入力欄・リンク等の操作では背面の会話を送らず、自由行動・終了画面でも背景入力を処理しない。
- 3行確認用の文章はテスト用に限定し、本編シナリオへ残さない。

### 3行を超える本文のページ送り（確定）

- 本文は実際の表示幅・使用フォント・文字サイズ・明示改行を考慮し、最大3行のページに分割する。文字数だけで一律に区切らない。
- スクロールや切り捨てで処理せず、全文を順番に読めるようにする。日本語・絵文字（結合文字や複数コードポイントの絵文字を含む）を欠落・破損させない。
- 文字送り中の操作は現在ページの全文表示とする。表示完了後の操作は、次ページがあればそのページへ移り、文字送りを開始する。
- 最終ページの表示完了後、次の操作で既存のシナリオ進行を1回だけ実行する。
- ▼は現在ページの表示完了後に表示する。途中ページでは次ページ、最終ページではシナリオ進行の操作を示す。
- 途中ページへの移動や全文表示では、情報取得・フラグ更新などの会話完了処理を発生させない。これらは最終ページを読み終えて進行するときに既存の処理として1回だけ適用する。
- ページ送りは表示上の分割であり、本文を読む途中に別のシナリオノードへ進めない。

## Free Action（確定）

### 表示対象と順序

最大5コマンドの候補を、次の固定順で扱う。

1. 聞く
2. 調べる
3. 考える
4. 整理する
5. 移動

- システムが選択可能と判定した項目だけを表示する。常に5項目を表示する仕様ではない。
- 未解放・条件未達・未実装の項目は非表示とし、無効ボタンや未実装表示で場所を埋めない。
- 実行済みでも再選択可能な項目は表示を維持する。既読であることだけを非表示の理由にしない。
- 表示対象を絞った後も上記の相対順序を維持する。
- 第1部の仮シナリオでは「考える」を `think.requiredInformation` の全項目取得後に限って表示する。情報なし・一部取得・1件不足では項目を描画せず、空き行も残さない。
- 全必須情報の取得後は次フェーズへの入口として「考える」だけを表示し、「聞く」「調べる」の実行要求も拒否する。補助調査と再聴取は取得完了前に行う。これは既読による非表示ではなく、取得完了による進行段階の切替として扱う。
- 「考える」の表示・実行条件は `hasAllInformation` とし、システムが実行時にも再検証する。余分・重複情報は不足項目の代わりにならない。SaveData version 2とノードIDは変更せず、過去のセーブで `think` ノードを復元した場合の不足反応は互換性のため残す。
- 選択可能項目が0件の場合は、コマンド・空き行・無効項目を表示しない。
- シナリオ／システム側で、会話への復帰など次の進行手段を明示し、操作不能のまま停止させない。
- Free Actionノードには`empty: { label, next }`を必ず指定する。0件時のみ指定の復帰操作を表示し、`continue`要求をシステムで再検証して会話ノードへ進める。定義時に復帰先の存在と会話ノードであることを確認する。
- UIは指定された進行手段を表示・実行へ渡す。UIが独自に遷移先を決めたり、未実装コマンドを補充したりしない。

### レイアウトと操作

| 項目 | 確定値・ルール |
| --- | --- |
| 項目群の位置 | ゲーム領域の右側・垂直中央。項目数が変わっても項目群全体を中央配置 |
| 右余白 | ブラウザー全体ではなくゲーム領域幅の8%（1920px基準で約154px、仮採用）。以前のDialogue Windowとの右端一致・5%ルールを置き換える |
| 横幅 | 420px（仮採用） |
| 各コマンド高さ | 最小88px（仮採用）。長い項目は折り返して必要な高さを確保 |
| 項目間隔 | 12px |
| 内側余白 | 16px |
| 文字 | 36px、左揃え、オフホワイト |
| アイコン | 44px |
| 通常背景 | 各項目に半透明青黒。外側に巨大な一枚パネルを置かない |
| 強調 | hover／focus／選択中のみ、左側の真鍮色ラインと控えめな文字・背景変更 |
| 選択演出 | 150msの短いハイライト後に操作へ遷移 |

各行が最小高さの場合、項目群の高さは `88 × 項目数 + 12 × (項目数 - 1)` pxとする（1件以上）。非表示項目の空き行を残さない。「行動を選択してください」のような見出しは表示しない。

### 聞く／調べるのサブメニュー

- トップと同じ右側領域、パネル幅420px、ゲーム領域幅8%の右余白を使い、トップとサブの右端を統一する。選択肢の文字はメイン・サブとも36pxとし、長い項目は縮小せず折り返して行高を増やす。補助表示は同じ行内の別列に置き、項目名と重ねない。独立した各行の背景・枠・余白を使う。下部の大きな2カラムパネルへ切り替えない。
- 見出しは選択肢と同じ幅420pxの背景付きヘッダーに収める。背景は選択肢と同系統の青黒半透明、文字は不透明な明るい真鍮色・32px・ウェイト600とする。左右の内側余白と透明な左枠は選択肢に合わせ、文字の左端をそろえる。
- ヘッダー高さ64px、最初の選択肢との間隔12pxを仮採用する（1920×1080基準）。ヘッダーはクリック対象にせず、ホバー演出を付けない。短い装飾線は表示しない。ヘッダーを含むメニュー全体をゲーム領域の縦中央に配置する。
- 未実行／NEW／既読／調査済みを各行の右側へ小さく表示する。NEWのみアンバー、それ以外はグレー系とする。
- 再選択可能な既読・調査済み項目と「戻る」を維持する。条件付き項目にもシステム側の表示・実行判定を適用する。
- サブメニューの`parent.commandId`から見出しを、`parent.nodeId`から親への復帰先をシステムが解決する。「戻る」はシステム生成の復帰操作で、項目データの`next`や`updates`を使わず、情報取得・フラグ更新・会話完了処理を起こさない。
- 項目IDは`id`、表示名は`label`、選択可否は実装有無・条件、実行済み状態は`progressId`（省略時は項目ID）とGameStateから導出する。項目の`next`が結果会話、結果会話の`next`が読了後の復帰先を明示する。

## システムとUIの分担（確定）

- システム側が現在状態・解放条件・実装有無などから選択可否を判定する。
- UIはシステムが選択可能と判定した項目だけを描画する。UI独自の判定やダミー項目の追加を行わない。
- 実行時にもシステム側で選択可否を再検証する。150msの選択演出中に条件が変わった場合も、実行時の判定を優先する。
- 非表示項目への直接の実行要求、未知の項目、選択不可となった項目は拒否する。進行や取得情報などのゲーム状態を更新しない。
- 表示可否と実行可否の規則を一致させる。UIで隠すだけを実行防止策にしない。
- メニュー全体で選択演出を排他制御し、同一・別項目の連続クリックでも一つの要求のみ発行する。発行元ノードIDと入力世代を実行時に検証し、遷移後・再訪後・ロード前・MENU開閉前の古い入力を拒否する。会話も最終読了要求を一度だけ発行する。
- GameState、SaveData version 2、既存の進行・解放条件・セーブ／ロードとの整合性を保つ。


## 調査記録（閲覧専用）

- 上部HUDの「調査記録」から開く。タブ順は **人物 → 証拠 → 出来事 → 持ち物**。
- 人物は関係者の情報と聞き取った内容、証拠は取得した手がかり・写真・調査結果、出来事は判明した経緯を時系列で表示する。出来事の順序は情報の取得順と区別する。
- 持ち物の基本項目はスマホ・電子タバコ・名刺。スマホ本体は持ち物、スマホで撮った証拠写真は証拠とし、同じ項目IDを両分類に表示しない。
- 取得前の項目名・伏せ字・未解放枠は表示しない。各記録と人物の追加説明は現在のGameStateに対応する取得情報／調査済み対象から導出する。記録ゼロの分類は「記録はありません」と表示する。
- 中央パネルはゲーム領域の幅85%・高さ80%（仮採用）。背景・人物を暗く残す。青黒半透明背景と細い真鍮色枠を使い、上部左に「調査記録」、右に「× 閉じる」を置く。
- タイトル40px、一覧・本文32px（1920×1080基準でゲーム領域に比例縮小）。タイトル下に4タブを置き、選択中は真鍮色の下線。本体は左30%の一覧、右70%の詳細。選択項目は控えめな真鍮色で強調する。
- 一覧と詳細は各領域内で独立してスクロールし、パネル・背面ページはスクロールさせない。画像は任意とし、画像なし・読み込み失敗でも説明を表示する。
- 開いている間は背面の会話・タイプライター・選択操作を停止し、進行中の選択演出をキャンセルする。閉じるとノード・現在ページ・文字送り位置・進捗を維持して再開する。MENUと同時には操作しない。
- キーボードはタブで左右矢印／Home／End、項目でEnter／Space、閉じるボタン／Escapeを使用できる。Tab／Shift+Tabのフォーカスはモーダル内に閉じ込め、閉じた後はHUDの呼び出しボタンへ戻す。
- 今回は閲覧のみ。使用・提示・整理する操作、未読管理を追加しない。

### 既存データとの対応・不足

- 調査記録の定義は`src/data/investigation.ts`、取得判定・分類は`src/features/story/investigation.ts`。既存の`acquiredInformation`と`inspectedTargets`を参照するため、GameState・SaveData version 2に項目を追加しない。
- 第1部の仮シナリオには調査記録の説明・時系列の管理がなかったため、既存の仮台詞に基づく定義を追加した。`missing_date`と`disappearance_timing`、`brother_recent`と`last_known_activity`は別名として一つの出来事にまとめる。
- 初期の人物一覧は空。兄の人物情報は`brother_profile`取得後に表示する。澪の人物情報は兄・失踪・最近の兄・事故のいずれかの聞き取り完了後、または`client`調査後に表示する。同じ澪の記録へ取得済みの話題だけ追記し、手元の緊張などの観察は`client`調査後のみ表示する。導入での自動登録は行わない。
- 出来事の日時は「以前」「最後の連絡時」「三日前から」の相対表現のみ。事故の詳細・暦日・写真の日付の具体値は未設定であり、推測で補わない。
- 基本の持ち物は固定の閲覧定義。所持品の取得・消費・個数管理は既存GameStateにないため対象外。
- 証拠写真用の画像やスマホ撮影処理は未実装。既存の「兄の写真」は説明のみで表示する。見本画像の文章・人物画は実データに使用しない。
- 未読／既読の記録管理は既存機能にないため未対応。自由行動の話題既読状態とは別の管理として今後検討する。

### 調査記録の受入・検証範囲

- 指定タブ順・一覧／詳細切替、取得前の項目非表示、基本の持ち物のみの初期表示、証拠とのID非重複、出来事の時系列と別名統合をNodeテストで確認済み。
- `tests/investigationBrowser.test.mjs`を外部Playwright環境で実行し、1920×1080・1366×768でパネル85%×80%、左右30%／70%、記録ゼロ・25件一覧・長文・画像なし／失敗、独立スクロール、背面停止・復帰、キーボードとフォーカス制限、SaveData不変と既存選択操作をChromiumで確認済み。
- Firefox・Safari・スマホ実機は未検証。ストレス検証用の多数・長文記録はブラウザーテスト内のみで追加し、本編へ残さない。

## 保存・MENUからの復帰方針

- SaveData version 2の形式を維持し、シーン・人物・ページ番号・文字送り位置・入力世代は保存しない。保存ノードIDからシーンと表示人物を、保存進捗から選択可能項目を導出する。
- ロードでは保存したサブメニューノードもそのまま復元する。会話をロードした場合は、そのノードの先頭ページ・文字送り先頭から再開する。同じノードの再ロードでも同様とする。
- MENU開閉だけでは現在ページ・文字送り位置を維持する。開いている間は文字送りと背面入力を停止し、進行中の選択演出をキャンセルする。閉じた後にキャンセル済みの選択を実行しない。
- 入力世代は実行中のみの情報で、ロード・ノード遷移・MENU開閉時に更新する。保存データ互換性には影響しない。

| 5コマンド常時表示 | 最大5候補のうち選択可能な項目のみ表示 |
| 未実装項目の無効表示 | Free Actionの未実装項目は非表示 |
| Free Action中の湊だけ左配置／モードに応じた人物移動 | シーンで人物を決め、湊は原則左。モード・話者変更だけでは人物や配置を変えない |

以前の指示や概要に上記の旧方針が残っている場合、設計判断には本書を優先する。

## 受入基準

以下は今後の実装を検証する基準であり、現行実装で全件合格したという記録ではない。

- 1920×1080と1366×768で、通常GAMEとFree Actionの表示・文字・操作が成立する。
- 通常GAMEの会話欄は指定寸法・透明度を満たし、3行本文、名前、▼が重ならない。
- 1920×1080と1366×768で、3行を超える長文・明示改行・日本語・絵文字をページ分割して全文読める。文字の欠落や切り捨て、スクロールがなく、各ページの名前・本文・▼が重ならない。
- 文字送り中の操作で現在ページを全文表示し、表示完了後に次ページへ移る。▼は現在ページの表示完了後にのみ表示される。
- 途中ページではシナリオ進行・情報取得・フラグ更新を行わず、最終ページ完了後の操作で既存の進行と会話完了処理を1回だけ実行する。
- Free Actionでは会話欄を表示しない。コマンド0件からシステム指定で会話に復帰した場合は通常GAMEとして会話欄を表示する。
- 選択可能コマンドが0件でも、シナリオ指定の進行手段があり、進行不能にならない。空き行・無効項目・UI独自の遷移先は追加しない。
- PCの異なる画面サイズで、Free Actionトップと聞く／調べるのサブメニューの右端・幅・文字36pxが一致する。ゲーム領域幅の8%の右余白と共通パネル幅420pxを維持し、画面外にはみ出さない。人物との重なりによって人物配置を変更しない。
- 長い選択肢を文字縮小せず折り返し、補助表示を含めて重なり・欠けがない。最大5項目でもゲーム領域に収まり、折り返し後の項目群を垂直中央に置く。
- 選択可能項目が1〜5件の各場合に、右側垂直中央と固定順序を維持し、空き行を残さない。
- 未解放・条件未達・未実装の項目が描画されない。これらへの直接の実行要求もシステム側で拒否され、ゲーム状態が変わらない。
- 選択演出中に選択不可になった項目は実行しない。
- 再選択可能な既読・調査済み項目は表示され、再実行できる。
- シーン指定に従い、湊のみは原則左、湊と相手は左右、湊不在では中央／右に配置される。
- 話者変更や通常GAME／Free Actionの切替だけでは、表示人物・配置を変更しない。同一シーン・同一表示指定で確認する。
- 人物とコマンドが重なっても、UIが人物を自動移動しない。
- MENUを開くと右側項目が非表示・操作不可になり、閉じると現在の選択可能項目が戻る。
- 会話進行、文字送り、条件付き分岐、セーブ／ロード／削除が維持され、既存テストが通る。
- DEV操作はゲーム領域外で利用でき、▼に重ならない。

### 「タバコを吸う」ヒント演出（現行試作）

以下は確定仕様ではなく、現行ブランチにある検証用の試作動作である。

- HUDの「タバコを吸う」から開始し、喫煙可否に応じて`src/assets/cutins/minato-smoking.png`または`minato-non-smoking.png`をゲーム領域いっぱいに表示する。背景・通常立ち絵・HUDは挿絵の上へ重ねず、既存のDialogue Window／タイプライターで動作文、続けて仮ヒントを表示する。
- 吸える場所では電子タバコを手に取って吸う文章を表示する。吸えない場所では口元に手をやり、吸わない文章を表示する。喫煙可否にかかわらずヒントを読める。
- Dialogue Windowは通常会話と同じ位置・サイズ・青黒背景・文字送り・ページ送りを使う。喫煙・非喫煙の動作文とヒントでは話者名および話者名下のラインを表示しない。画像読み込みに失敗した場合は暗い背景へフォールバックし、動作文とヒントの操作を継続できる。
- ヒント文は固定の仮文「手掛かりに迷ったら、澪から話を聞き直し、兄の写真も確かめてみよう。」。現在の情報状態やシナリオノードには連動しない。
- 演出中は既存の再生一時停止とメッセージウィンドウを使い、背後の会話・選択・HUDを操作不能にする。前面ウィンドウに背面停止用の減光を適用せず、通常会話と同じ背景の濃さを保つ。読了中はDialogue Windowへフォーカスし、読了後はHUDの呼び出しボタンへ戻す。開始時の会話ページ／タイプライター位置、Free Action／サブメニュー、人物配置、GameState、情報・フラグ、SaveDataは変更しない。
- 開発モードのゲーム領域外DEV欄から「吸える場所／吸えない場所」を切り替える。選択値は開発プレビュー用のUI状態であり、セーブしない。通常の製品ビルドではこの切替欄を表示しない。
- `考える`は従来どおり必須情報の揃い方で依頼受諾フローを判定する。喫煙ヒントを読んでも条件達成や進行は起きず、`考える`の条件も変更しない。
- 画像は各状態を示す一枚絵で、動き・煙の追加演出はない。喫煙可否の本編判定、取得情報に応じたヒント接続、製品用の動作文・ヒントは未実装。DEV切替と固定文は検証用であり、製品シナリオではない。
- Chromiumブラウザーテスト`tests/smokingBrowser.test.mjs`を1920×1080・1366×768で実行し、両画像の全画面比率・表示と通常メッセージボックスとの寸法一致、両方の文面、読了後の会話／Free Action／サブメニュー復帰、文字送り位置・LocalStorageの不変、画像読み込み失敗時のフォールバックを確認する。

## 開発用の調査記録プレビュー

- 開発モードのゲーム領域外DEV欄から明示的に開く。通常／一部空／全部空／多数・長文／画像なしを選択でき、タイトル内に「DEV・UI確認用」と表示する。
- 本編の記録定義やGameStateを変更せず、プレビュー専用の記録配列を閲覧UIへ渡す。情報取得・フラグ・SaveDataへの登録はしない。通常のHUDから開く記録にはサンプルを表示しない。
- 人物は佐伯湊・澪の既存通常PNGを参照し、一覧と詳細の表示領域内でトリミングする。元画像は変更しない。
- 証拠は架空の現場写真（DEV SVG）と聞き取りメモ（画像なし）。持ち物はスマホ・電子タバコ・名刺のDEV SVGを使い、証拠とID・分類を分ける。画像は`src/dev/assets/`、定義は`src/dev/investigationPreview.ts`。本番アセットではない。
- 架空の出来事3件は発生日時順に並べ、別の情報取得日時を詳細に表示する。実際のシナリオ日時を設定するものではない。
- 空分類は左の一覧だけに「記録はありません」と表示し、右詳細は空にする。記録のある分類を開くたび先頭を自動選択する。

### 調査記録中の背面・人物画像

- 記録を開いている間は背面の会話ウィンドウ全体（話者名・本文・送り記号）を非表示にする。会話コンポーネントは保持したまま停止し、閉じた際は現在ページと文字送り位置から再開する。非表示による進行・情報更新は行わない。背景と人物の暗い表示は維持する。
- 人物一覧は顔〜肩を中心とする80px角のサムネイル、詳細は胸上を中心とする320px角の表示領域を仮採用（1920×1080基準）。領域内で既存画像を拡大・トリミングし、元ファイルは変更しない。説明は画像領域の後に余白を置いて表示する。人物画像がない場合は名称・説明のみを表示する。

### 第1部の聞き取りと記録の接続

- 「失踪について」の会話ノード`missing`を読み終えて自由行動へ戻ると、既存の`missing_date`／`disappearance_timing`取得により澪の人物記録に聞き取り内容を表示し、出来事「兄との連絡が途絶える」を表示する。会話途中・全文表示・途中ページ送り・記録開閉では取得しない。
- 「兄について」→`brother_profile`、「最近の兄について」→`brother_recent`／`last_known_activity`、「過去の事故について」→`past_accident`も既存の完了処理を使う。澪の人物記録に取得した話題のみ追加し、出来事は以前の事故→最後の連絡時→三日前からの連絡途絶の順に並べる。暦日・時刻・情報取得日時は現行のシナリオ／GameStateにないため補わない。
- 聞き取りと観察は同一の澪の記録（既存ID `client-observation`）へ統合する。記録定義の`alternativeSources`で複数の取得経路を認め、個別の詳細は各情報の取得判定を維持する。再聴取しても既存のID重複防止により情報・記録は重複しない。
- 記録そのものは保存せず、SaveData version 2の取得情報・調査済み対象からロード時も導出する。DEVサンプルを取得情報へ登録しない。
