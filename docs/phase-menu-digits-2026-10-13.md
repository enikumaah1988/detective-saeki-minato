# 話題段階の切替と全角数字表示

基点はmain `d3fc2b6`。PMから受領したプレイ指摘２件を、既存レイアウトと保存形式の範囲内で修正した。標準運用はPM資料ブランチ`docs/pm-standard-operation`の`docs/ai-development/README.md`を参照した。

## 話題切替後の復帰先

`topicTransitions`のつなぎ会話を読了したとき、話題一覧ではなく現在場面のメインコマンド一覧へ戻す。対象は次の４箇所。

| 場面 | 切替会話ID | 切替内容 |
| --- | --- | --- |
| P1-03 | p1-basics-to-search | 帰らなくなった日・最後の朝・連絡 → 勤務先・捜索状況 |
| P1-03 | p1-search-to-background | 勤務先・捜索状況 → 兄の普段の様子・相談内容の確認 |
| P1-05 | p1-request-to-materials | 調査の進め方・範囲 → 写真・連絡先 |
| P1-05 | p1-materials-to-farewell | 写真・連絡先 → 帰ってきた場合・見送り |

同じ話題段階の会話後は元の一覧を維持する。例えば写真の受取後に連絡先が追加される場合は話題一覧のまま。場面をまたぐ既存の進行、話題の末尾追加、既読状態、条件は変更しない。旧つなぎ会話IDからのロードも維持する。

## 数字の表示

本文・話者名・選択肢・見出し・日時・調査記録・会話履歴・扉絵タイトル・システム通知・音量の表示文字列に共通の全角数字変換を適用する。例：`10月8日 14:30` → `１０月８日 １４:３０`、`40%` → `４０%`。漢数字や句読点・記号は保持する。本文は変換後の文字幅を使って改ページする。

原稿の本文、内部ID、時計情報、数値、条件、パス、SaveData version 2、履歴保存内容は変換しない。音量の画面表示が`４０%`でも保存値は数値40、スライダー値は4のまま。

## 検証

- ロジック回帰：１２５件合格、失敗０件。ブラウザー環境を指定しない実行でブラウザー５５件はスキップし、関連ケースを別実行。
- 関連ブラウザー：Windows Chromium、1920×1080・1366×768で１２件合格。話題切替４箇所、同一段階の一覧保持、人物観察、ロード・旧保存、受取表示、記録・履歴・日時・音量を確認。
- 全角数字の長文：両解像度で５ページ。各ページ３行以内、送り記号と非重複、全ページを連結すると変換後の全文と一致。結合文字・絵文字・漢数字を保持。
- TypeScript型チェックとVite本番ビルド成功。ビルドに500kB超のチャンク警告あり。今回は分割方針を変更していない。
- 検証用サーバー5191は検証終了時に停止。他担当が起動したサーバーは操作していない。

Firefox/Safari・スマートフォンは未確認。今回の依頼範囲に判断待ち・持ち越しはない。mainへの直接コミット・マージは行わない。

## 追加：出発前の必須段取りを連続会話にする

`p1-company-call`（会社への連絡）、`p1-mio-role`（留守中の対応）、`p2-depart`（出発の挨拶）は、前提情報が揃ったら通常の会話送りで続ける。以前の「話す→澪→会社への連絡」「留守中の対応」「会社への訪問」という個別選択は不要になる。

写真を確認する調査操作は維持し、その読了でF10を取得してから電話の会話を開始する。電話の読了でF11と受付の情報、留守中の会話の読了でF12、出発の挨拶の読了で出発準備の情報を取得する。本文・情報ID・取得条件は維持。任意の「あかりの様子」は出発前の場面へ持ち越し、「移動→外に出る」は手動の確定操作として残す。

旧保存が未完了段取りの一覧にある場合は、取得済み情報に応じた会話から再開する。会話途中の保存位置は維持し、ロードだけで未読の情報は取得しない。完了した段取りは再開しない。SaveData version 2を維持する。

追加後の検証：関連ロジック１１件合格、一式では１２７件合格・失敗０件（ブラウザー５７件は環境を指定しない実行でスキップ）。Windows Chromiumの２解像度で関連ブラウザー８件合格。連続会話・途中保存とロード・旧一覧保存の再開・任意話題・移動、前回の話題切替後のメイン復帰と通常会話の一覧保持を確認。型チェックと本番ビルド成功（500kB超チャンク警告は継続）。検証用サーバー5191は停止済み。他担当のサーバーは操作していない。
