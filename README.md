# 探偵 佐伯湊 / Detective Saeki Minato

## 概要

「探偵 佐伯湊 / Detective Saeki Minato」は、現代を舞台にした探偵アドベンチャーゲーム（ADV）の個人開発プロジェクトです。現在は、ローカルシナリオを使った最小 ADV の会話・選択肢分岐を実装しています。

React + TypeScript + Vite の最小構成を導入済みです。バックエンドは未実装で、将来の API 連携に向けたディレクトリを用意しています。

## 実装済みの最小 ADV

- IDから解決した背景・立ち絵画像と、画像未設定・読み込み失敗時のプレースホルダー表示
- 話者名とセリフの表示、「次へ」ボタンでの会話進行
- 2つの選択肢による会話分岐、終了後の「最初から」操作
- 型付きのローカルシナリオデータと UI・進行ロジックの分離

起動すると第1話「灰色の証言」第1部「依頼」を通して遊べる仮シナリオを表示します。正式シナリオではありません。画面上部で従来の会話・分岐仮シーンにも切り替えられます。切替時は初期化され、ロードは保存したシーンを選んで実行してください。

LocalStorage による1スロットのセーブ／ロード・削除を実装しています。Backend / API 通信、音声・BGM・SE、Android / iOS 対応は未実装です。

## ID ベースの表示定義

シナリオの `scenes` に背景IDと人物一覧（人物ID・表情ID・配置）を定義し、各ノードの `sceneId` から表示を解決します。会話の `speakerId` は表示人物とは独立して話者名を解決します。旧形式の `stage` も互換読み込みできます。画像パスや人物の表示名はシナリオに記載しません。

`src/data/presentation.ts` に背景定義（ID・表示名・任意の `imageSrc`）とキャラクター定義（ID・表示名・表情一覧）を分離しています。各表情も ID・表示名・任意の `imageSrc` を持ちます。話者名はキャラクター定義から解決します。

現在は`src/assets/backgrounds/office-afternoon.png` と、`src/assets/characters/minato/`・`mio/` のPNG画像を定義側で `new URL(..., import.meta.url).href` により参照しています。本番画像への差し替えも定義側の `imageSrc` だけで行え、シナリオ変更は不要です。

未登録の ID は代替名で表示します。画像が未設定または読み込みに失敗した場合も、背景・人物名・表情の表示を保持します。表情 ID は画面、背景・人物 ID は DOM の `data-*` 属性でも確認できます。

## 仮画像の確認方法

会話・分岐の仮シーンを選ぶと、事務所背景と佐伯湊の `normal` を表示します。会話を進めて「話を聞こう」を選ぶと `serious` に切り替わります。「先にコーヒーを頼む」では `normal` を維持し、相澤澪は `normal` を表示します。

画像読み込み失敗を目視確認する場合は、ブラウザーの開発者ツールで対象の画像リクエストをブロックし、キャッシュを無効にして再読み込みしてください。失敗した画像だけが非表示となり、背景の代替色・人物名・表情・会話操作を維持します。確認後はブロックを解除して再読み込みしてください。製品コードには検証専用の切替機能を追加していません。

未登録 ID・未登録表情・画像未設定は `tests/presentation.test.mjs` と `tests/stage.test.mjs` で確認しています。

## ADV の現在状態

`GameState`（`src/types/gameState.ts`）は `scenarioId`・`nodeId` に加え、`flags`・`heardTopics`・`inspectedTargets`・`acquiredInformation` を保持します。背景・キャラクター・表情・話者・選択肢・終了状態は現在ノードから導出し、重複して保存しません。

`src/features/story/state.ts` に初期化、現在ノードの導出、`advance`・`choose`・`continue`・`reset` の状態遷移を集約しています。次ノードの判定自体は既存の `progression.ts` が担当します。シナリオを切り替える際は、その ID を StoryPlayer の `key` に指定して初期化します。

ゲーム状態は JSON 化できます。同じシナリオ定義があれば現在画面と話題・調査の進捗を再現できますが、会話全文の履歴は保持していません。セーブデータの検証は実装済みで、シナリオ改訂により参照先が削除された場合は復元を拒否します。LocalStorage への永続化と検証済み状態の復元を実装しています。バックログは未実装です。

## セーブデータ形式と検証

`SaveData`（`src/types/saveData.ts`）は `GameState` とは別型で、現在は version 2 で、シナリオ ID・ノード ID と4つの進捗項目を保存します。version 1 は進捗項目を空として復元します。表示情報や画像、React 固有の値は保存しません。

`src/features/story/saveData.ts` の `createSaveData(state)` が変換を行います。`restoreSaveData(input, scenarios)` は未知データを、形式・対応 version・シナリオ ID・ノード ID の順に検証します。`parseSaveData(json, scenarios)` は JSON の解析失敗も扱います。シナリオ一覧は呼び出し側で渡し、余分な項目は復元状態へ引き継ぎません。

成功は `{ ok: true, state }`、失敗は `{ ok: false, reason }` を返します。理由コードは `invalid-format`・`unsupported-version`・`unknown-scenario`・`unknown-node` です。失敗時の自動移動・リセットは行いません。

version 1・2 の読み込みに対応し、新規保存は version 2 です。進捗項目の型も検証し、ID 配列の重複を除去します。専用のセーブ／ロード画面は未実装です。

## LocalStorage のセーブ／ロード

画面左上の「メニュー」を開いて「セーブ」で現在位置を保存し、「ロード」で保存時点へ戻ります。ページ再読み込み後は初期画面から始まり、「ロード」を押すと復元できます。「セーブデータ削除」は保存データだけを削除し、現在の会話は変更しません。

保存キーは既存データを読み込むため `detective-saeki-minato.save.v1` を維持しています（キーの名前とデータ内 version は別です）。1スロットのみです。セーブは上書きされます。保存対象は version 付きの現在位置と進捗状態で、ロード時に既存の形式・version・参照先検証を通します。成功・保存なし・読み込み失敗・削除結果を画面に表示し、失敗時は現在位置を維持します。

`src/features/story/storage.ts` が保存・取得・検証・削除、`SaveControls.tsx` が操作とメッセージ、reducer の `restore` action が状態反映を担当します。ブラウザーの保存機能が拒否された場合や容量不足も失敗結果として扱います。

同じブラウザー・同じオリジン（ホストとポートを含む）でのみデータを共有します。ブラウザーデータの削除によってセーブも消えます。複数スロット、クラウド同期、オートセーブは未実装です。

動作確認は「会話を進める → セーブ → さらに進める → ロード → 保存位置へ戻る → 再読み込み → ロード → 削除 → ロードで保存データなし」の順で行えます。

## 第1部「依頼」の通し方

新規開始から「次へ」で事務所の日常・依頼人の来訪・依頼提示を読み、自由行動へ進みます。「聞く」で「兄について」「失踪について」「最近の兄について」「過去の事故について」を聞き終えると、必須情報が揃い「考える」が表示されます。選択すると判断・依頼受諾・第1部完了へ進めます。その後の「次へ」で第2部開始用の仮ノードへ到達します。手動の状態変更は不要です。

「見る／調べる」の依頼人・兄の写真は補助調査です。途中セーブ・ロードでも継続できます。旧セーブから必須情報不足の `think` ノードを復元した場合は、互換用リアクションを表示して自由行動へ戻ります。本番の台詞と第2部本編は未実装です。

## 自由行動の最小ループ

「聞く」から話題、「見る／調べる」から調査対象を選び、結果の会話で「次へ」を押すと状態更新を適用して自由行動メニューへ戻ります。「戻る」だけでは進捗を更新しません。「兄について」を聞くと `brother`・`brother_profile` を記録し、「最近の兄について」が表示可能になります。写真の調査は `photo`・`photo_date` とフラグを記録します。

仮データは `src/data/scenario/freeActionDemo.ts` にあります。通常の `dialogue`・`choice` に `topic`・`inspect` を追加し、会話や選択肢の `updates` に `setFlag`・`addHeardTopic`・`addInspectedTarget`・`addInformation` を指定できます。ID の追加は重複しません。

選択肢の任意の `condition` は `flag`・`heardTopic`・`inspectedTarget`・`hasInformation`・`hasAllInformation` の単一条件です。`freeAction.ts` が GameState から表示対象を導出し、reducer も未解放の選択を拒否します。解放済み話題の重複状態や汎用 AND/OR 式は持ちません。

「考える」は `think.requiredInformation` の全項目を `acquiredInformation` に取得した場合だけ自由行動に表示されます。直接の選択要求や選択演出中の条件失効もシステム側で拒否します。旧セーブで不足情報のまま `think` ノードを復元した場合の材料不足／中間整理リアクションは互換性のため維持しています。全必須情報が揃うと「単なる失踪ではない」と判断して依頼受諾シーンへ進みます。余分な情報や情報数だけでは不足項目を満たせません。

必須情報は「兄について」「失踪について」「最近の兄について」「過去の事故について」で取得します。「過去の事故について」は最近の兄の話を聞くと表示されます。思考内容と遷移先は仮シナリオで定義し、`thinking.ts` で現在状態から表示会話を導出します。SaveData version 2と既存ノードIDは変更していません。複雑な推理・正解選択・ゲームオーバーは実装していません。

## 現行実装の UI の基本構成

背景をゲーム領域いっぱいに表示し、人物と下部の濃色・半透明の会話ウィンドウを重ねています。通常会話はクリック／タップ、またはフォーカス後の Enter／Space で進行します。右下の小さな送り記号が目印です。「考える」は背景を軽く暗くし、佐伯の内心として表示します。

自由行動の「聞く・調べる・考える」と話題・調査一覧は画面右側の専用領域に縦型表示します。操作中は下部の大きな選択パネルを出さず、背景を残します。条件付きで解放された未読項目は NEW、実行済みは既読／調査済みと表示し、再選択できます。NEW 通知の履歴は別途保存しません。

保存操作はゲーム画面左上の MENU にまとめています。開発用シーン切替はゲーム領域の下の DEV 欄へ分離し、常時タイトルや素材名のラベルは本編から外しています。画像未設定・失敗時の代替表示は維持しています。

現行実装ではシーンの`characters`で人物ID・表情・配置を指定します。第1部は導入の湊単独から依頼シーンの湊左・澪右へ明示的に切り替わり、その後は話者・会話／思考／自由行動の切替で人物や配置を変えません。人物とコマンドの重なり回避による自動移動は行いません。

UI の配色・MENU とコマンドの密度・文字とアイコンのサイズは `reference/ui/ui-reference.png` を参考にしています。参考画像を実装用アセットとして使用していません。人物・背景・衣装・画風は取り込んでいません。

PC版UIは1920×1080・16:9を基準に、画面内へ同比率で縮小します。会話は実際の表示幅とフォントを測って最大3行にページ分割します。文字送り中は現在ページを全文表示し、完了後は次ページへ進み、最終ページの完了後だけシナリオ進行・情報更新を行います。結合文字や複合絵文字も一つの文字送り単位として扱います。自由行動の既存3操作は短い選択表示後に遷移します。「調査記録」は閲覧UIを実装済みです。「タバコを吸う」は動作文と仮ヒントを表示する試作です。開発モードでは吸える／吸えない場所を切替できます。読むだけでは情報取得・進行・セーブ状態は変わりません。本編のヒント接続と専用演出素材は未実装です。Free Actionの「整理する」「移動」は未実装のため非表示で、ゲーム内日時も未設定です。表示寸法は `src/features/story/story.css` のCSS変数、文字送り速度は `DialogueWindow.tsx`、選択表示時間は `CommandButton.tsx` で調整できます。

## PC版UIの確定仕様と未対応事項

確定仕様は [PC版通常GAME／Free Action UI仕様書](docs/pc-game-ui.md) を参照してください。以下は現行実装の対応状況です。未対応の内容は明示しています。

- 人物は`scenes`とノードの`sceneId`から解決し、話者・会話／思考／Free Action切替だけでは変更しません。湊単独は原則左（明示右も可）、湊＋相手は左右の2人、湊不在は明示中央／右に対応しています。複数の相手の同時表示は対象外です。
- Free Actionは「聞く／調べる／考える／整理する／移動」のうち、システムが選択可能と判定した項目だけを固定順で表示し、実行時にも再検証します。Free Actionは `choice` ノードの `mode: 'free-action'` で通常分岐と区別し、固定順と実装有無をシステム側で管理します。条件未達・未実装項目の非表示と実行拒否、文字36px・アイコン44pxは実装済みです。「整理する」「移動」の操作自体は未実装です。
- 最大3行のページ送りは実装済みです。途中ページでは情報取得・フラグ更新を行わず、最終読了時のみ1回処理します。ノード・入力世代の検証とメニュー全体の選択排他制御で、連続クリックや古い入力を拒否します。
- コマンド0件時はシナリオの`empty`で指定した会話復帰操作を表示し、実行時にも0件か再検証します。サブメニューの親タイトル・復帰先はシステム側で解決し、戻るでは情報やフラグを更新しません。

仕様書の受入基準には、両PC解像度での長文・改行・日本語・絵文字の欠落防止と名前・本文・▼の非重複、最終ページのみの会話完了処理、コマンド0件でも進行不能にならないことを含めています。今回、1920×1080・1366×768のChromiumとNodeテストでこれらの進行・表示を確認しています。検証環境と未検証範囲は仕様書末尾に記載しています。

### PC会話・MENU・ロードの復帰

SaveData version 2を維持しています。保存したサブメニューはそのまま復元し、会話をロードした場合は保存ノードの先頭ページから文字送りを再開します。MENUの開閉だけでは現在ページと文字送り位置を保持し、MENU中は背面操作・文字送りを停止、選択演出はキャンセルします。

ロジック・UI回帰テストは`node --test --test-isolation=none tests/*.test.mjs`、型チェックとビルドは`npm run build`で確認できます。ブラウザーテストには別途PlaywrightとChromiumの検証環境を使用します（プロジェクト依存には追加していません）。開発サーバー起動後、`SAEKI_PLAYWRIGHT_PATH`にPlaywrightのモジュールパス、`SAEKI_BASE_URL`にサーバーURLを指定して`node --test tests/pcBrowser.test.mjs`を実行します。未指定時はブラウザーテストのみスキップします。Firefox・Safari・スマホ実機は未検証です。

### 調査記録

上部の「調査記録」から、人物・証拠・出来事・持ち物を一覧／詳細で閲覧できます。取得済み情報・調査結果のみを表示し、出来事は取得順によらず時系列で並べます。基本の持ち物はスマホ・電子タバコ・名刺です。閲覧中は背面の会話・文字送り・選択を停止し、閉じると元の位置から再開します。キーボード操作・Escapeでの閉じる操作に対応しています。

記録は既存進捗から導出し、SaveData version 2を維持します。写真画像、所持品の使用・提示・増減、未読管理は未実装です。現在の仮データの不足と検証方法は[PC版UI仕様書](docs/pc-game-ui.md)を参照してください。ブラウザー確認用テストは`tests/investigationBrowser.test.mjs`です。

開発サーバーではゲーム領域の下の「DEV 調査記録UIプレビュー」を開き、通常／一部空／全部空／多数・長文／画像なしを選べます。本編の進捗・セーブへは反映しません。人物画像は既存PNGを領域内でトリミングし、証拠・持ち物の仮SVGは `src/dev/assets/`、サンプル定義は `src/dev/investigationPreview.ts` に配置しています。プレビューは開発モード限定で、通常起動時には自動表示せず、製品ビルドにはサンプルを含めません。

第1部の「聞く」で澪から兄・失踪・最近の兄・過去の事故の話を聞き終えると、調査記録の澪の人物情報へ取得した内容が反映されます。「失踪について」では出来事「兄との連絡が途絶える」も確認できます。未取得の話題は表示せず、再聴取・セーブ／ロード後も同じ記録として扱います。会話途中の記録閲覧では情報を先取りしません。
